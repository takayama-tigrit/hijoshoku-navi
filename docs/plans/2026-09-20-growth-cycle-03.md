# 非常食ナビ：28日・集客検証サイクル03

**期間：2026-09-20〜2026-10-18（JST）。担当：サイト運営者／実行担当。**

## 結論

記事の見た目を繰り返し作り直す段階から、**必要な読者へ届け、候補を選べるか確かめる段階**へ移る。検索だけを待たず無料の公開接点も試す。ただし新規記事数と作業回数を成果にはしない。

- 対象：家庭備蓄を買い足す際、必要量・調理条件・セットの中身が結びつかず、買うものを決められない人。
- 約束：主食・おかず・補助食品の役割と条件を見て、買い足す物を絞れる。足りている人には追加購入を促さない。
- 当面の成果：自己QA以外の適合する訪問、販売先への送客、最初の承認成果。大量記事、順位、表示回数だけでは事業成功としない。
- 初期の代替手段は公的備蓄ガイド＋メーカー情報＋EC検索。追加価値はこの間の比較・数量確認の手間を減らすこと。優位性は未実証。

## 状態と権限

前サイクルの実装・本番QAは[公開PR #10](https://github.com/takayama-tigrit/hijoshoku-navi/pull/10)。5記事、画像比較4記事は維持。検索成果・読者理解・収益効果は未実証。今後の編集も、**画像＋太字・ブランド色マーカーだけで候補／条件／注意／次行動が分かる**ことをスマホ実表示で確認する。

本サイクルではサイト内調査、改稿、独立レビュー、PR/CI/公開/検証、条件内の既存ASP運用、承認された発信先での無料公開投稿を実行対象にする。以前の「その都度公開承認」「新cronなし」はそのサイクルの境界であり、今回は本書の範囲を優先する。

次は含めない：有料広告・追加契約・新アカウント・本人確認・支払変更・資格/経験の創作・秘密情報の取得/移管・別事業アカウントの無確認流用・DM/メール配信。既存サービス以外の新規支出上限0円。既存AI実行費・制作/校正時間は無料と見なさず未集計として残す。

**全般的な公開承認と、ASPが要求する人間の校正・事実確認は別。** 新しい食品の仕様・安全条件を含むAI本文は、確認日・確認者・差分が記録されるまで下書き。人間校正は短い差分にまとめ、既存の確認済み本文を毎回読み直してもらわない。独立AIレビューでも代替しない。

## 自動化の実態と限界

既存 `Site quality` workflowへ日次のpublic-only jobを追加する。新サーバー、credential、新解析、通知先を作らない。対象は固定5記事とsitemap/robotsの7 GETだけ。広告リンクを辿らず、JSを実行せず、GA4自己PVを作らない。ただしホスト側のHTTPアクセスログには残り得る。

- `python3 tests/public-seo.spec.py`：不正canonical/noindex/header/H1/schema/404/403/robots/sitemap等をfixtureで否定検証。fixtureは実流入ではない。
- `python3 scripts/check-public-seo.py --output <new-path>.json`：手動の実公開確認。既存ファイルは上書きしない。
- GitHub schedule：9/21〜10/18 09:23 JST。GitHubの混雑で遅延・不実行の可能性があるため、厳密な時刻保証はしない。
- 定期実行はJST日付guardで期間外HTTPを止める。cron式自体は年次構文なので、10/18判断時に登録の解除/更新が必要。期限後も無制限に観測し続ける設計ではない。
- GitHub Actions runと35日保持のsanitized JSONが証跡。既存GitHub通知設定に従い、新規Discord/メール送信を追加しない。失敗の発見と自動修正は別。本jobは修正・投稿・記事生成を行わない。
- **GA4/GSC/ASPの定期取得と、定期的な記事改善はまだ自動稼働していない。** 対象に接続されたAPIがなく、ブラウザセッションが必要。別事業のMCPを流用しない。実行担当が継続タスクに9/21（集計可否）、9/26（発信先可否）、9/27・10/4・10/18（診断）を保持し、対話セッション起動時に期限超過から再開する。これは人手起動依存の計画であり、日付到来だけで実行担当を起動する経路は未稼働。自走改善とは報告せず、取得経路・稼働証跡が成立するまで「完全自動PDCA」と呼ばない。
- Mac側schedulerの不稼働を、このサイトの公開監視のためにruntime変更・別profile移管で解消しない。公開GET部分だけ既存GitHubで実行する。

## 停止・回復

食品安全/仕様誤認、画像権利・商品不一致、ASP否認/提携解除、個人情報漏洩、独立レビューBLOCKで該当公開・送信を止める。技術監視が403の場合は「取得失敗」でありサイトダウン確定ではない。別の通常経路で再確認し、WAF/認証を回避しない。

rollbackは当該PRの差分revert。定期監視だけならworkflowのschedule/public-only jobを無効化できる。サイトの承認済み本文・広告・計測の設定は本実装で変更しない。

- 2026-09-20：対象管理画面の再取得。GSCは処理中、GA4は自己QAを分離できない集計、ASP媒体は審査中・楽天提携中。自然顧客数を0と置かない。非公開生証跡は公開repoに格納しない。

- 公開・hosted起動・次回定刻のfireは、それぞれ実際の実行結果で別に判定する。
