# Mobile UX cycle 04 — 数量入力のタップ操作

## 目的と範囲

スマートフォンで在庫を確認する読者が、キーボードや日数ピッカーを開かずに数量を変え、不足分と買い物メモを得られるようにする。運営者からの「全数量を−1/+1で変更」「デザインシステムに沿うボタン」という具体的な指摘への是正。

対象はhome/guide共通の計算・確認・保存UIと、その実部品見本。承認済みの白・細罫線・黒灰文字・黄色アクセント、写真、アイコン、本文・出典は維持する。新商品本文、ASP申請、SNS投稿、解析イベントの追加、計測の自走化は対象外。

## 数値仮説と検証

これは操作上の摩擦を減らす設計仮説であり、実読者の利用率や収益改善の予測ではない。

| 指標・分母 | 変更前の実測 | 設計上の目標 | ローカル検証 |
|---|---|---|---|
| 数量4項目のうち±1が両方ある項目 | 2/4（人数・主食） | 4/4 | 4/4をタップし値を照合 |
| 320/390/430pxの入力グリッド | 全て2列 | 全て1列 | computed gridで1列 |
| 320pxの入力領域/主確認ボタン幅 | 250px / 165.375px | 同じ幅 | 250px / 250px |
| 操作時に数値input等へ移るフォーカス | 未取得 | 0回 | 数量増減で0回 |
| 主増減ボタンのタップ領域 | 旧基準44px以上 | 48px以上 | 52px角、水補助48px高 |
| 新しい受入プローブ | 65件不合格 | 全件合格 | 65件合格 |

計測単位はローカルのブラウザQA。人による所要時間・誤操作・理解率、実機iPhone/Safari、SEO・自然流入・売上の効果は未測定。仮の顧客改善率を実測として記載しない。別の成果観測計画は `2026-09-20-growth-cycle-03.md` に維持する。

## 実装と安全条件

- 4項目を共通stepper partialにし、ラベルと操作領域を分離。数字の直接入力は補助として残す。
- 水は±1Lのほか±0.5L/±2L。日数は3/7日のネイティブラジオで、矢印キーにも対応。
- 単一の `adjustQuantity` が増減の計算とdisabled状態を決める。水は整数mLで演算し、空・不正・範囲外・超精度を有効値に補正しない。
- CSSの旧高詳細度2列指定と旧補助ボタン規則を除き、モバイル先行の部品規則に置換。高さと境界色はeditorialのroot tokenへ追加。
- 計算例と入力済み在庫の来歴、空欄とゼロの区別、保存直前の再計算、自由記述の文字列扱い、JS無効/読込失敗時の無効化、ローカルのみの処理を維持。
- CTAは黄色の主アクションと白の保存アクション。結果ジャンプが固定ナビに隠れないことを確認。
- `npm run style-guide` のローカル限定見本でも実際のplannerを表示・操作できる。見本をproductionのcontent/sitemapへ追加しない。

## 検証手順と記録の読み方

- `node tests/planner-mobile.spec.mjs`: 320/390/430/1440px、home/guide、タップ・キーボード・上下限・精度・メモ実保存を検証。`ARTIFACT_DIR`指定時は変更前後のスクリーンショットとJSONを保存。
- 先に未修正実装で65件のREDを確認。期待どおり旧2列・不足する増減・旧ボタン・日数pickerで失敗した。実装後に65件GREEN。
- `npm test`: 数値/出典/画像/公開SEO/記事UX/ライセンス/保存/XSS/解析非送信/noJSを含む全suiteがローカル成功。既存select操作はradio操作へ置換、境界は「押せるが無視」から「disabledかつ変更なし」へ強化し、計算・保存assertを削っていない。
- 実部品見本追加も `quantity-stepper` 未存在でRED、追加後GREEN。
- 独立技術・プライバシーレビューと視覚・User-Fitレビュー、CI、merge後の公開DOM/asset bytes/操作の最終状態は対応PRの証跡に記録する。ローカル成功だけで公開完了とはしない。

## 停止と戻し方

数値・来歴・非送信の回帰、required reviewerのBLOCK、画面の横溢れ、保存内容の不一致があれば公開を止める。差分は単一PRへまとめ、公開後の問題はそのmerge commitのrevertをレビュー・CI経由で適用する。データ移行・削除・課金設定変更はない。
