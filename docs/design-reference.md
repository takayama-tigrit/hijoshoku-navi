# 編集・画面設計の参照基準

## 主参照

ROOMIEを主参照とする。生活用品の写真を起点に記事を選び、記事中でも具体物の写真と短い説明を交互に読む編集型を使う。mybest・360LiFEも候補として確認したが、自社の大量商品テスト・専門家の実測評価を前提にした順位や評価点は、メーカー仕様を確認する現在の運用では再現できない。

- トップ: https://www.roomie.jp/
- 記事: https://www.roomie.jp/2026/09/1883684/
- 観測日: 2026-09-19
- 読者規模: 運営会社の[媒体紹介](https://www.mediagene.co.jp/media/roomie)に月間15,500,000+ PV、月間4,800,000 UUと掲載。計測年月・集計定義は記載されていないため、観測日の実測値とは扱わない。媒体単独の売上・利益は確認できていない。

mybestの[公式サービス説明](https://my-best.com/company/service)も月間ユーザー3,000万人超への到達を掲載するが、ROOMIEのUUとは時期・定義・地域範囲が揃わないため倍率比較しない。360LiFEは今回確認した[公式の運営説明](https://360life.shinyusha.co.jp/list/about)ではPV・UU・利益を確認できず、知名度を実績の代用にはしない。ROOMIEを選ぶ理由は、公表された読者規模に加え、写真と具体的な生活上の判断を中心にした画面設計が、3記事・実食なしという現在の条件に適合するため。実体験の信頼や現行デザインの収益貢献まで再現できるとは考えない。

主参照は複数媒体の好きな部品を寄せ集めるためのものではない。共通の編集型を先に定め、備蓄の数量・選択条件・安全性に必要な部分だけ差分を持たせる。参照先の文章・画像・ロゴ・図版・CSSソースは転載しない。

## 実画面から採る型

PCは1440px、スマートフォンは390pxのモバイルUAで確認。単にデスクトップ画面を狭めると別の画面を観測する媒体があるため、初回ロード時のUAと画面幅を区別した。

| 対象 | 主参照での観測 | このサイトの実装条件 |
|---|---|---|
| トップの主欄 | 幅800px。先頭は写真付きの記事を約523pxと247pxに非対称配置 | 記事3本を主役にし、巨大な宣言コピーと計算フォームを冒頭に置かない |
| トップの脇欄 | 約300px。主欄との余白60px | 在庫確認・食品選択・編集方針の実在する導線。架空の人気順位や広告枠は作らない |
| 記事カード | 四角い写真、枠・影なし。写真の下に18px/27pxの見出しと小さい情報 | 写真→固有の見出し→カテゴリ・日付。説明文・ボタン・チップを全部のカードに積まない |
| スマホの一覧 | 主記事は幅広写真。続く記事は写真左・見出し右 | 冒頭3記事で閲覧先を選べる。横長記事行で画像とタイトルをまとめる |
| 記事冒頭 | 大写真→見出し→著者・日付 | 同じ順番を基本に、一般イメージの限定と比較範囲を近接表示する |
| 記事本文PC | 幅650px、16px、行高29.6px、段落下24px | 約650px・16px・行高1.85を基準に長い行を避ける |
| 記事本文スマホ | 幅350px、左右20px、h1 20px/30px | 左右20pxを基本。320pxでも横溢れや小さすぎる注記を発生させない |
| h2 | 20px/37px、PC上60px/下30px、SP上40px/下20px | 説明予定ではなく、章の具体的な判断対象を見出しにする |
| 視覚表現 | 白・薄灰の面、無彩色の文字、限定したアクセント。角丸・影に依存しない | アイボリー・深緑・明朝・大型スローガンの旧型から切り替える |

数値は観測したページの値であり、普遍的な最適値ではない。実装で変える場合は理由を明記する。

## 意図的に模倣しないもの

- 参照先の個人の購入・利用体験、名前・顔・推薦。こちらの実体験として書かない。
- 実測の裏付けがない人気・PV表示・点数・総合順位。
- ロゴやサイト名、第三者の画像・装飾、同一の文章、取得したHTML/CSS。
- 読者の操作を妨げる広告や巨大な空白。広告のない現状にダミーを置かない。
- 薄すぎる小さい注記。こちらでは本文・図の条件・ライセンスが読めることを優先する。

## 備蓄メディア固有の差分

1. 記事冒頭の候補・原材料・次行動は消さない。図付きの選択メモを細い罫線と通常の文字組で配置し、320/390pxでも最初の具体行動を750px以内に置く。写真先行でも、巨大写真のために判断を遅らせない。
2. 計算機はトップ下段と備蓄ガイドで利用できるようにする。食品だけの保存、水未確認の表示、不正入力・入力変更時の古い計算結果の破棄を維持する。
3. 写真は使い回しを増やすためでなく、対象・状況を示すために置く。一般食品を掲載商品の現物に見せない。帰属表示を保つ。
4. 数量図・正確な補助表・条件・出典を維持する。詳細を折り畳んでも判断に必要な警告を隠さない。

## 受入条件

- 参照画面と制作物のトップ・記事冒頭・本文をPC/SPで並べ、写真比率、情報順序、本文幅、行間、余白、カード形状、段落の長さを独立に確認する。
- CSSの色だけを変えたものや、旧heroへ画像を追加しただけでは不合格。
- 3記事の図・数値・安全条件・参照URL・内部リンク、食品単独保存、水計算、noJS時の非送信を既存テストで再確認する。
- 機能のPASSを文体・実画面の合格と同一視しない。参照と似ていても架空の経験や比較があれば不合格。
- 規模のある媒体を参照したことを、当サイトの検索順位・売上改善の証明にしない。
