# 編集・画面設計の参照基準

## 採用する型

主参照は **北欧、暮らしの道具店**。ROOMIEを参照した旧版は、この設計の基準にしない。複数媒体の部品を混ぜず、北欧暮らしのヘッダー、文字組、写真と余白、記事の流れを一つの体系として再実装する。

- トップ: https://hokuohkurashi.com/
- 代表記事: https://hokuohkurashi.com/note/1000000901
- 観測日: 2026-09-19
- 観測条件: PC 1440×960、スマートフォン390×960・モバイルUAの新規ブラウザcontext。
- 採用理由: 題材の写真、短い具体的な言葉、読みものと選択の導線を通じて世界観を作る方向を、運営者が選択した。

北欧暮らしにはオリジナル商品もある。「自社商品を持たないサイトの成功例」とは扱わない。[公式決算説明資料](https://contents.xj-storage.jp/xcontents/AS04874/d067153e/afba/437e/a51b/b994a4182f96/140120260911534856.pdf)の2026年7月期セグメント売上は10,010百万円で、EC等を含む。これは記事広告収入でも、デザインによる増収の因果証拠でもない。

## 再現するデザインシステム

| 対象 | 実画面の観測値・構造 | 再実装の条件 |
|---|---|---|
| PCヘッダー | 上部固定、初期100px高、スクロール後70px。左にブランド、右に細線アイコン＋ラベル | 横長ブランド領域と小さいナビの対比を保つ |
| SPヘッダー | 上部固定73pxの5項目ナビ、約61pxのブランド段 | ナビ→ブランドの順。ブランドと案内帯はスクロールで退場、ナビは残す |
| 案内帯 | 薄灰、PC46px高 | 実在する案内・カテゴリへ接続。偽セールや送料無料表示は移さない |

| トップ副記事 | 各364px、間隔24px | PC2列、SP主要記事は縦積み。3記事を水増ししない |
| トップ主写真 | PC752×351px、SP390×約182px（幅比約2.14） | SP主要3記事の写真は左右画面端まで。説明・captionは左右16px |
| トップSP説明欄 | 358px、左右16px | 写真全幅と文章の余白を分離。記事本文の左右16pxは維持 |
| 記事カード見出し | PC15px、SP14px、行高22.4px | 大見出しだらけにせず、写真に対して控えめな文字 |

| 配色・装飾 | 白、薄灰、黒灰の文字、黄色の小アクセント | 写真の色を主役にし、影・丸角・グラデーションで飾らない |
| フォント | 游ゴシック系と日本語system fallback | 本文の書体・太さ・行間を揃える。ブランド文字は独自表現 |

初回仕様ではSPトップの写真幅を記事本文と同じ358pxと誤読し、PC主写真も高さ376pxとした。独立レビューの指摘を受けてDOMを再取得し、上表の写真寸法とスクロール時の挙動へ訂正した。古い寸法のテスト成功は再現の証拠にしない。

主特集と代表記事扉は、異なる写真カット・被写体スケール・段差・重なり・白い抜け・コピーの配置を組み合わせる。単写真＋大きな無地コピー面への簡略化や、同じ写真を反復しただけの構図では合格にしない。全カットの原本出典・帰属は写真クレジットで維持し、写真下へ免責を反復しない。

測定値は代表ページの観測値であり、普遍的な最適値ではない。小さい画面、アクセシビリティ、原本の権利、安全情報に必要な変更は、比較レビューで理由と差分を残す。

## 共通の型と題材固有の内容

初号は非常食ナビとし、既存Hugo内で共通部品を作る。新しい量産サービス、独立CMS、別リポジトリ、複雑なテーマ継承はこの段階では追加しない。

**共通部品**

- 色、余白、幅、文字のデザイントークン
- アイコン付きヘッダー、案内帯、メニュー、フッター
- 写真と短いコピーの特集枠、記事カード
- 記事の外枠、連載名、タイトル、編集主体、写真、本文見出し、出典表示、関連記事
- レスポンシブ、キーボード操作、写真クレジットへの導線

**題材ごとに差し替えるもの**

- サイト名、短い説明、案内、ナビ、編集方針
- 特集に出す実記事のパス、写真ID、特集コピー、連載名
- ブランドの象徴・favicon・写真用途に合うalt。食品の記号を共通partialへ固定しない
- 記事扉はトップ特集への選抜と独立して定義できること。未設定なら通常写真へ戻し、空のコピー面を出さない
- 記事本文、対象商品・出典、比較の条件
- 題材固有の道具。非常食では在庫メモ・水計算・数量図

共通化は文書だけでなく、設定差し替えテストで確認する。食品以外の題材では、題材に合う独自素材・記号・captionでPC/SPのhome/記事/メニュー/footerを表示する。食品写真を使った文字列置換だけを交換可能性の証拠にしない。別題材fixtureのビルドは交換可能性の検証であり、別サイト運用や収益の実績には数えない。複数サイトへの展開は初号の実利用を確認してから行う。

## 非常食ナビの世界観

「いつもの食事のそばに、無理なく備えを置く」。災害への恐怖や大量購入を煽るのではなく、家にある食品・飲料水を知り、食べられる条件を確かめ、足りない分を選ぶ。

- 編集者の架空の生活、家族、実食、買ってよかった感想は作らない。
- 写真は具体的な食品や食事の場面を示す。一般写真を掲載商品・完成した非常食備蓄の証拠にしない。
- 氷水ボトルの青い写真や雑然とした収納写真を、世界観を決める主役として置かない。
- ブランドの世界観と、安全情報・比較の根拠を両立する。警告を小さく薄くして雰囲気を作らない。
- カート、会員機能、在庫、送料無料、人気順位など、存在しない機能や実績を見せない。

## 移さないもの

参照先の名称・ロゴ・黄色い花・馬のアイコン・文章・写真・図版・HTML/CSSのソースは転載しない。細線アイコン、写真の構図、余白や文字の階層という役割を独自に実装する。フォントや写真に必要なライセンスを維持する。

大量の記事棚、広告、動画・アプリの追従案内、購入機能を外形のために複製しない。3本の実記事で成立する構成にする。

## 既存条件の移行

- ROOMIE型の「写真→タイトル」「本文650px」「800px＋300pxの脇欄」は上記の新基準に置き換える。
- 初期画面の具体的な行動は残す。タイトル近傍に実在する在庫・比較への短いアンカーを置き、320/390pxで750px以内を確認する。候補一覧全体を冒頭へ詰め込む旧条件にはしない。
- 3記事の数値、数量図、出典、アレルギー、水温・待ち時間、賞味期限、栄養の限定は保全する。
- 食品だけのメモ保存、水未確認、在庫ゼロ、不正入力、古い計算結果の破棄、JS無効・読込失敗時の入力非送信を維持する。
- 一般写真を商品証拠として置かず、権利表記を独立クレジットへ保つ。通常の食品写真を実食に見せない。

## 視覚の反復評価

トップ、記事冒頭、本文を参照と同じ画面幅で比較する。次の5項目を各0〜4で記録する。

1. 背景・配色
2. 文字組・太さ・行間
3. ヘッダー・ナビ・部品
4. 写真の占有面積・配置・装飾
5. 余白・構成・情報の順序

0=未再現、1=大きな差、2=一部一致、3=概ね一致、4=規定値・役割に忠実。採点には比較画面と残る差分を添える。背景・文字・ヘッダー等の重大な未達を総合点で相殺しない。異なる写真の生ピクセル差を再現度としない。

自己評価→修正→独立した仕様・視覚レビュー→技術レビューの順に行う。初期実装の目安20分、その後最大3回の修正を一区切りとし、停滞時は未達を報告する。時間上限到達は合格ではない。

動くトップ・代表記事を運営者が確認してから公開へ進む。技術テスト成功や高い自己採点を、見た目の承認・検索順位・売上改善の証明にしない。

## 承認済みベースラインと運用

現在の方向性、とくに豊富なアイコンは運営者承認済み。以後は新しい参照を探すのではなく、このベースラインからの差分を検査する。安全性やライセンスの問題以外で構図・題材の写真を再設計しない。

| 正本 | 管理するもの |
|---|---|
| `assets/css/editorial.css` の `:root` | 色、フォント、752/518px幅、本文16/28px、参考13px/1.65、段落余白、ヘッダー寸法 |
| 同CSSのthree-cut composition | トップ752:351、記事4:5、3カットの段差・重なり・object-position |
| `data/editorial.json` | サイトidentity、symbol/favicon、4ナビ＋menu、3記事の実パス、写真ID、記事扉、フッター |
| `layouts/_partials/editorial-icon.html` | 独自の細線6種類。本文の食品アイコンはarticle-choiceの実部品 |
| `data/article-evidence.json` | 読者に番号を見せない命題・表行の出典対応 |

`npm run style-guide`は実際のHugo部品による文字階層・アイコン・カード・写真構図・選択メモ・参考の見本を一時ディレクトリに生成し、末尾にパスを出す。公開サイトには追加しない。

変更は①正本の最小差分、②新挙動のRED、③実装とGREEN、④全回帰、⑤390/1440の比較の順。幾何・固定nav・メニュー/noJS・アイコン数・実体の数値/安全情報・出典マッピング・ライセンスを守る。監査用の説明はdocsとtestsへ、読みものに必要な短い参考だけを読者へ残す。

写真の免責と許諾details、冒頭の編集disclosure、英語Sourcesと本文の角括弧番号を必須とした旧契約は廃止。必要な権利と根拠は削除ではなく移設し、CSS非表示でDOMへ残す実装は禁止する。
