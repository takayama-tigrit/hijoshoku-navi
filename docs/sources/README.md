# 記事の出典記録

対象記事は `data/article-evidence.json` のレジストリで管理しています。既存3記事に、セット内容の確認記事と温め不要のおかず記事の2記事を追加しました。登録記事数と公開数は別に確認します。各一次情報の取得日は `retrieval.json`、本文の命題との対応はレジストリに保存しています。

## 保存内容

- `ledger.json`：出典番号・URL・確認に使った短い引用。
- `retrieval.json`：HTTPステータス、最終URL、確認日時、抜粋ファイルのSHA-256。レスポンスを検証した場合はresponse hash、ブラウザDOM取得はDOM text hashと取得方法を区別します。
- `excerpts/*.txt`：主張を確認するために必要な箇所だけを抜粋。`[別抜粋]`は連続していない箇所の境界です。メーカーのパッケージ画像を読んだものはvisual transcriptionとし、参照画像URL/hashを記録します。
- `verify.py`：台帳と引用の整合、抜粋ハッシュ、出典一覧、主要仕様表、人数・日数の計算を検査するスクリプト。

商品ページの「5年保存」「そのまま食べられる」は画像代替テキストにも記載されているため、該当する短いHTMLタグを保存しています。商品画像と全文HTMLは同梱していません。

このディレクトリはHugoの公開出力には含まれません。ただし、このGitHubリポジトリ自体は公開されています。

## 再検証

リポジトリ直下で実行します。Pythonの標準ライブラリのみを使用します。

```sh
python3 docs/sources/verify.py
npm test
```

出典番号は記事間で共通の内部IDです。読者向け画面は番号ではなく、記事が使う一次情報へのリンクを末尾に表示します。スクリプトは登録記事の命題対応・引用集合と台帳集合の一致、未登録記事、改ざん、未来の取得日も検査します。記事MDはevidenceKeyと登録を必須とし、例外はセクション用`_index.md`とコードで明示した運営/プライバシー/写真クレジットの3ページだけです。表示日`accessed`は取得日時`checked_at`に記録されたタイムゾーンでの暦日と一致させます。下書きは通常ビルドから除外したまま検証します。

検査は、保存した情報と記事の整合性を確認するものです。メーカーの最新ページを再取得した証明や、解釈が正しいことの自動判定にはなりません。仕様の更新時には一次情報を再確認し、本文・抜粋・台帳・検証条件をまとめて更新してください。

## 確認対象と限界

- アルファ米は尾西の通常100gタイプ3品に限定し、別シリーズの仕様を混ぜていません。
- 「5年保存」は各商品ページの表示です。公式FAQの一般説明を使って購入後の残存期限を推定していません。
- 商品情報は確認日現在のものです。価格・販売実績・人気順位・実食結果・到着個体の期限は調査対象外です。
- 献立の記入例や主食の合計カロリーは、個人の必要栄養量を満たす完成メニューではありません。
- 保管条件、原材料、アレルギー表示は、購入する現物の表示を優先します。
- 内容検証、画面検証、Cloudflare Pagesでの公開確認は別の検証です。
